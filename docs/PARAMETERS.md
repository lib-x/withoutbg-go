# 参数获取与封装记录

本文记录 `withoutbg-go` 用到的每个参数从哪里来、为什么是这个值、改了会怎样。写作目标是让没有视觉背景的人也能复现同样的过程。

## 1. 第一手来源：模型自带的 sidecar

这个模型仓库在 ONNX 文件旁边放了一份 `<model>.onnx.json`，README 明确说"先读 sidecar，它是 `canvas_size`、输入输出名、精度、模型版本和 SHA256 的权威来源"。库的做法完全照此：`LoadSidecar` 解析它，`New` 用它填默认值，再和 ONNX 图逐项校验。

sidecar 的实际内容（version 10.0.0 导出）：

```json
{
  "canvas_size": 448,
  "matting_input_size": 448,
  "opset_version": 18,
  "precision": "fp32",
  "variant": "oss",
  "depth_variant": "dav2s",
  "convnext_size": "base",
  "model_version": "10.0.0",
  "input_name": "rgb",
  "output_name": "alpha",
  "input_dtype": "float32",
  "input_shape": [1, 3, 448, 448],
  "output_shape": [1, 1, 448, 448],
  "size_mb": 454.5,
  "sha256": "29930e48e9d5ecc56d6486c53c35a4c1470566c2a3359fa180b08c8d3c34ef0f",
  "mae": 3.67e-08,
  "max_abs": 3.0e-05
}
```

要点：

- **`canvas_size` 决定一切几何**：输入画布、letterbox 的目标尺寸、输出蒙版的尺寸都用它，所以库把它作为 `Config.CanvasSize` 的默认值，缺了直接报错而不是猜 448。
- **`input_name` / `output_name` 是 `rgb` / `alpha`**：库拿它们建会话，并校验图里的张量名一致。名字对不上说明模型文件和 sidecar 不是一对，属于必须报错的情况。
- **`sha256` 可以核对**：官方给出的哈希和我们下载到的文件一致（已核对）。库把它做成可选的 `VerifyModelSHA256`，因为校验要读完 455MB。
- **`mae` / `max_abs` 是导出质量指标**：官方声明 ONNX 导出和参考实现的平均误差是 3.67e-08，属于浮点噪声级别。这两项只能说明"导出没走样"，不代表模型本身的精度。

## 2. 预处理：文档写死的五步

模型 README 的 "Preprocessing (required)" 一节给出了五步，库里逐条对应：

| 步骤 | 文档要求 | 库里的实现 | 为什么 |
|---|---|---|---|
| 1 | 转 RGB | `resizeRGBFloat` 取 `color.Color` 的 RGB 分量 | 输入张量名就叫 `rgb`，契约如此 |
| 2 | 读 `canvas_size` | `Config.CanvasSize`（默认取 sidecar） | 几何参数只有一个来源，避免多处写死 |
| 3 | 长边缩放到 `canvas_size`，保持比例 | `fit()`：`scale = canvas / max(w,h)`，`newW = round(w*scale)`，最小 1 像素 | 保持比例避免形变；最小 1 像素避免极端长条被压成 0 |
| 4 | 贴到黑底画布左上角 | 预分配全零张量，只写左上角区域 | 黑 = 0，正好等于"未写入"的零值，无需额外填充代码 |
| 5 | 归一化到 `[0,1]`，HWC 转 CHW | 除以 65535 后写入 NCHW 平面 | 注意这里是**只除以最大值**，没有减均值除标准差，和 PP-OCR 那类模型不同 |

一个容易写错的地方：第 3 步是"长边缩放到 448"，不是"短边"也不是"固定 448×448 拉伸"。400×491 的竖图会变成 365×448，右侧留黑边；如果误做成拉伸，模型会把形变当成内容，边缘会糊。

双线性插值：官方示例用 PIL 的 `BILINEAR`，库里的 `resizeRGBFloat` 用像素中心映射的双线性采样，边界做钳制。

## 3. 后处理：裁回、放大、量化

| 步骤 | 文档要求 | 库里的实现 | 为什么 |
|---|---|---|---|
| 1 | 把蒙版裁到缩放区域 | 取左上角 `newW × newH` 子块 | 画布右下是黑边，对应的蒙版值是 0；不裁的话黑边会把 alpha 拉低 |
| 2 | 缩回原图尺寸 | 双线性缩放到 `srcW × srcH` | 和官方一致；蒙版是连续量，双线性比最近邻更平滑 |
| 3 | 作为 PNG alpha 通道 | `composite()` 返回 `*image.NRGBA`：RGB 是原色，A 是蒙版 | 抠图的定义：颜色不动，只加透明度 |

裁剪这一步有个反直觉之处：**画布里的黑边不是"背景"，而是"不存在的区域"**。如果直接把整张 448×448 蒙版缩回原尺寸，竖图左右会各多出一条 alpha 接近 0 的窄带，人物边缘会被啃掉一圈。库里有一条专门的单元测试（`TestAlphaFromOutputCropsAndScales`）盯着这个裁剪。

## 4. 输出语义

输出是 `[0,1]` 的 alpha 蒙版，1 表示前景（保留），0 表示背景（去掉）。库把它量化成 8 位：`uint8(v*255 + 0.5)`，并钳制到 `[0,255]`。

判断输出对不对的办法（按可靠性排序）：

1. **和官方示例对比**：模型仓库给了三张三联图（原图 / 抠图 / 蒙版），库的 golden 测试就是拿第 1 格当输入、第 3 格当标准答案，算前景 IoU 和平均绝对误差
2. **看蒙版的分布**：全黑或全白说明输入预处理错了（比如没归一化、通道顺序错了、letterbox 搞成了拉伸）
3. **看边缘**：主体边缘应该是渐变的过渡带；如果边缘是一圈硬锯齿，多半是缩放或裁剪的几何有问题
4. **置信度之类的指标这个模型没有**：蒙版本身是连续量，只能靠和参考结果比对，或者人工看

## 4b. 一个 Go 特有的坑：预乘 alpha

合成这一步看起来只是"把 alpha 挂上去"，但在 Go 里踩了一次坑，值得记下来。

`image.RGBA` 是**预乘**（alpha-premultiplied）容器：它存的 RGB 已经乘过 alpha，约定满足 `R,G,B ≤ A`。而抠图要表达的是"原色 + 独立的透明度"，是非预乘的。如果直接把原色写进 `image.RGBA` 并把 A 设成蒙版值，就违反了容器的约定，两个后果：

1. 用 `draw` 合成到别的背景上时，颜色会被重复乘一次 alpha，半透明区域发白
2. `png.Encode` 会按预乘语义把它反算成非预乘值：`r = r * 0xffff / a`。当 `r > a` 时这个除法溢出，再截断成 8 位就会**回绕**，得到完全错误的颜色（实测浅蓝 `(121,157,254)` 在 A≈128 的像素上变成了 `B=18` 的怪色）

正确的做法是返回 `*image.NRGBA`（非预乘容器），它存的正好是"原色 + alpha"，PNG 编码、`draw` 合成都按预期工作。库里的 `composite()` 返回 `*image.NRGBA`，并有一条单元测试盯着"透明像素的颜色也要原样保留"。

这个 bug 在整图看不出来（大面积不透明区域正常），只在半透明边缘出现彩色杂斑，一开始还怀疑是模型输出有问题，最后靠"取像素值对比源图和输出图"定位。

## 5. 已知边界与取舍

| 边界 | 原因 | 影响 |
|---|---|---|
| 最大 448 像素 | 模型输入是固定 `[1,3,448,448]`（sidecar 写死，图里没有动态维） | 大图先缩小，细发丝/细网格的高频细节会丢；需要更高精度只能自己分块后拼合 |
| 黑底 letterbox | 文档第 4 步要求 | 如果原图本身是黑底，边缘处模型可能分不清"内容黑"和"填充黑"；这是模型契约，不是库的选择 |
| 没有 refiner | sidecar 里 `"refiner": false` | 官方还有带 refiner 的变体，本导出没有；换变体时 sidecar 会变，契约校验会拦住不匹配 |
| CPU 执行 | pure-onnx 没有暴露执行提供者选择 | 455MB 模型在 CPU 上单张约 2 到 3 秒（本机 8 核，448×448 输入） |
| 只支持 fp32 | sidecar 的 `precision` 与 `input_dtype` 校验 | 换成 fp16/int8 导出会被拒绝，而不是静默算错 |
| 矢量图/卡通效果差 | 模型训练分布是照片，平涂色块没有纹理线索 | 实测卡通输入会留下大片背景；对照实验（去掉黑边填充、裁成正方形再推理）反而更差，说明与预处理无关 |

## 6. 参数封装方式

- 所有参数集中在 `Config`：`ModelPath`、`SidecarPath`、`CanvasSize`、`InputName`、`OutputName`、`VerifyModelSHA256`、`LibraryPath`
- 默认值来源有优先级：**调用方显式设置 > sidecar > 包内常量**，`applyDefaults` 负责填充，`validate` 只校验必需项，两者分开，方便单独检查有效配置
- sidecar 里的信息（画布、张量名、形状、哈希）不重复暴露成必填项，但都可通过 `Config` 覆盖，覆盖后仍会和图做一致性校验
- 全部参数都有测试：sidecar 解析（含缺字段和 dtype 不符的负例）、letterbox 几何、输入张量取值与填充、蒙版裁剪与缩放、量化、NRGBA 合成、流式接口往返，加上三个官方样本的 golden 对比和三张测试照片的蒙版分布检查
